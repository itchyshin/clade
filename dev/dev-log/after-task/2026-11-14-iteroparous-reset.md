# After task: restore repeated iteroparous reproduction

## 1. Goal

Correct a focal-reproduction flag defect discovered while testing foraging
and reproductive performance. Preserve the existing semelparous mortality
sequence and qualify quantitative results from the former kernel.

## 2. Implemented

Clear surviving agents' reproduced flags after kill_dead!/remove_dead!,
before the next reproductive phase. Eligible iteroparous agents can
reproduce on successive ticks. Semelparous mortality still reads the prior
episode flag first; parents complete their clutch and die at the next
mortality phase, on the following tick.

## 3a. Decisions and Rejected Alternatives

Do not clear at tick start: that would mask semelparous reproduction from
mortality. Do not clear inside create_offspring!: that would allow a second
focal episode within the same tick. Mate contributions are a separate
pathway and were never restricted by this focal flag.

Keep legacy raw data. Their numerical results remain descriptions of their
pinned source, but do not evaluate the corrected iteroparous model. New
performance runs must produce and assay their own corrected endpoint brains.

## 4. Files Touched

Clade.jl resets flags; types.jl explains the flag lifetime; new
Julia test_reproduction_reset.jl is registered in runtests.jl. R/config.R
clarifies repeated reproduction and next-tick semel death; default_specs.Rd
is generated by devtools::document(). NEWS, decisions and check log record
the correction. Earlier diversity, matched-founder and behavioural reports
receive explicit source qualifications without deleting their results.

## 6. Tests of the Tests

The tracked iteroparous founder regression fails on the original code.
Other fixtures retain a same-tick duplicate guard, allow an eligible attempt
after a failed low-energy attempt, permit a multi-offspring semel clutch,
and verify the parent's death at tick2 with its one focal episode intact.
These distinguish reset placement from simply removing the birth guard.

## 8. Consistency Audit

Public signatures, fields and default values are unchanged. This restores
the documented meaning of iteroparity. R documentation's immediate-death
wording is corrected to the existing next-tick order rather than silently
changing semel biology. Decisions log records the ordering; no Core
Contract row changes because no public signature/spec/default changes.

The earlier README/findings qualifications are additions. Historical data,
source hashes and original review records remain intact. No old figures
are silently represented as results of this corrected kernel. New API
examples are unnecessary; the existing life_history setting now follows
its stated rule, demonstrated by the regression fixture.

## 9. What Did Not Go Smoothly

Earlier life-history tests pinned the default string but did not test
successive focal episodes. Passing those tests and viable legacy runs did
not establish the intended reproductive mechanism. The population energy
and birth-rate discrepancy prompted the source review that found the bug.

## 10. Known Residuals

Seeded trajectories and demographic feedback change. Historical simulations
need rerunning before current-kernel quantitative claims. The preceding
behaviour results remain descriptive legacy evidence until re-evaluated.
The separate standard-log extinction-tick counter omission remains; the
performance observer captures actual counters and is not affected.
No release check or broad paper-vignette regeneration is claimed here.

## 11. Team Learning

Test a biological label through its state transitions, not only its
configuration value. Follow flags across ticks, mortality and repeated
calls. Preserve the distinction between focal episodes, clutch size and
mate contributions. Source-version parity cannot establish biological
correctness when both versions retain the same faulty rule.

## 12. Cross-Product Coverage

Tests cover haploid focal iteroparity, failed/same-tick attempts and
semelparous multi-offspring timing. The shared canonical phase governs
both ploidy regimes. This does NOT cover empirical validation, quantitative
scenario reproduction, release readiness or the completed performance
campaign, which follows after a corrected viability/runtime pilot.
