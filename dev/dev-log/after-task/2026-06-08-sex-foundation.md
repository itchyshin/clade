# After Task: Sex foundation (0.8.0)

## Goal

Ship the smallest foundation that gives `clade` a persistent sex
identity on agents, so subsequent work can introduce sex-specific
trait expression and mating-system structure. Motivated by the
Rees-Baylis et al. (2026, *Nature Communications*) paper-reproduction
target ("Asymmetric life-history trade-offs shape sex-biased longevity
patterns"), which requires sex-specific senescence onset ages
$M_m, M_f$ and therefore agents that know their own sex across their
lifetime. Full plan: `~/.claude/plans/parsed-watching-wolf.md`.

## Implemented

Branch `claude/sex-mating-system` off `main` at `9af0fa4`.

### Kernel (Julia)

1. **`Agent.sex::Int8`** added to the struct in `inst/julia/src/types.jl`
   (~1 byte/agent). Field is always allocated; semantics gated by the
   `sex_labels` spec.
2. **`_make_founder_agent` and `_make_offspring`** updated in
   `inst/julia/src/Clade.jl` and `inst/julia/src/reproduce.jl`:
   when `sex_labels = TRUE`, draw `sex` per `sex_ratio_primary`
   (proportion male); otherwise set `sex = 0`. `sex_determination`
   is read for validation — currently only `"random"` is supported;
   other values raise a clear error.
3. **`_find_mate()`** in `inst/julia/src/reproduce.jl` now filters
   candidates to opposite-sex when `sex_labels = TRUE`. Filter is
   bypassed when `sex_labels = FALSE` (preserves prior behaviour).
4. **Cost-split refactor for `parental_investment_evolution`** in
   `inst/julia/src/reproduce.jl`. Decoupled from the focal-agent
   convention: when `sex_labels = TRUE`, `female_investment` denotes
   the mother's share regardless of which partner initiated the
   reproductive event; cost-split swaps when focal is male. The
   `male_repro_cost` extra likewise targets whichever partner is
   male. When `sex_labels = FALSE`, the legacy "focal = implicit
   mother" semantics are preserved exactly. Decision recorded in
   `dev/dev-log/decisions.md`.
5. **`_agents_to_records`** in `inst/julia/src/Clade.jl` exports
   `sex` to R so it is visible in `env$agents[[i]]$sex`.

### R-side

1. **Three new specs in `R/config.R::default_specs()`**: `sex_labels =
   FALSE`, `sex_determination = "random"`, `sex_ratio_primary = 0.5`.
   Roxygen `@details` adds a "Sex foundation (0.8.0)" section

   primary-sex-ratio parameter.
2. **`R/utils.R`**: new `"Sex foundation"` group in `.SPEC_GROUPS`

## What didn't go smoothly

- **Julia env had a pre-existing dependency mismatch.** The pinned
  `Statistics v1.11.1` in `inst/julia/Manifest.toml` does not exist
  in Julia 1.10.0 (the version recorded in the manifest). The first
  smoke run failed with "ArgumentError: Package Statistics ... is
  required but does not seem to be installed." Resolved by
  `Pkg.rm("Statistics")` + `Pkg.add("Statistics")` which pulled the
  Julia-1.10-compatible v1.10.0. The refreshed `Manifest.toml` is
  included in this branch's diff; not caused by sex-foundation
  changes but surfaced by them.
- **First test pass failed on `max_ticks = 0L`.** The
  `.validate_specs` guard requires `max_ticks >= 1L`. I had set
  `max_ticks = 0L` intending a "founders-only" run; switched to
  `max_ticks = 1L` plus `min_repro_age = 99L` to prevent any
  reproduction in the test window, which serves the same purpose.
- **`env$agents` is a `JuliaArrayProxy`, not a plain list.** The
  proxy supports `length()` and `[[i]]` but not `as.list()` or
  bare `sapply(env$agents, ...)`. Test, vignette, and smoke
  script all use the cross-version-safe pattern
  `vapply(seq_len(length(env$agents)), function(i) ..., integer(1))`.

## Team learning

- **`_agents_to_records` is the boundary** for adding any new
  agent-level field that R-side code needs to see. Forgetting to
  append the new field there would have caused all sex-labels test
  failures.
- **`test-no-internal-leaks.R` enforces strict user-facing prose
  hygiene** for `Phase [AB]`, `Sergio`, `v0.8-core`, `CLAUDE.md`,
  `Tier [AB][0-5]?`, and bare `dev/(docs|design|audit)/...`. Worth
  remembering when drafting roxygen and vignettes for the upcoming
  sex-specific-trait release.
- **The diploid mechanism does not give us sex-specific expression
  for free.** `maternal_traits[TRAIT_AGING_RATE]` and
  `paternal_traits[TRAIT_AGING_RATE]` are two alleles of the same
  gene; what Rees-Baylis describe is two different genes (one for
  $M_m$, one for $M_f$) with sex-conditional expression. The
  upcoming sex-specific trait expression release will add new entries
  to the scalar trait table (`TRAIT_AGING_RATE_FEMALE_GENE`,
  `TRAIT_AGING_RATE_MALE_GENE`) and an expression helper that reads
  the sex-matching gene at birth.

## Known limitations

- Operational sex ratio (OSR) at equilibrium is sex-blind under this
  release: survival is identical across sexes, so OSR tracks
  `sex_ratio_primary` closely with no demographic feedback. Real
  rebalancing arrives once sex-specific traits and mating-system
  structure are added.
- No persistent pair bonds, mating groups, divorce dynamics, or
  min-harmonic mating function. `_find_mate()` still scans all
  opposite-sex neighbours each tick.
- `sex_determination` only supports `"random"` — `"chromosomal"`
  and `"environmental"` modes raise an explanatory error.
- Heritable / evolvable primary sex ratio (Trivers-Willard, Fisher
  sex ratios) is not supported — `sex_ratio_primary` is a fixed
  spec value, not a per-agent trait.
